# Data dictionary

All data is synthetic and generated by `fra/generate_data.py` (seed 42). Names, bank accounts and addresses are fictional. Currency is SGD. The review period is calendar year 2025.

## employees.csv (60 rows)
| Column | Description |
|---|---|
| employee_id | `E001`… |
| employee_name | Placeholder name |
| department | Operations, IT, Marketing, Facilities, HR, Sales, Finance |
| role | Staff, Manager, Director, CFO, AP Clerk |
| approval_limit | Delegated invoice approval limit: Manager 10,000; Director 50,000; CFO 250,000; others 0 |
| bank_account | Salary account (used by T04) |
| home_address | Home address (used by T04) |

## vendors.csv (249 rows)
| Column | Description |
|---|---|
| vendor_id | `V0001`… |
| vendor_name, category | Fictional name and spend category |
| created_date | Date the vendor master record was created |
| bank_account, address | Payment details on the vendor master |
| non_po_approved | True for utilities, which may bill without a PO |
| status | Active |

## purchase_orders.csv (2,745 rows)
| Column | Description |
|---|---|
| po_id | `PO00001`… |
| vendor_id, requester_id, department | Who raised the PO, for which vendor |
| po_date, po_amount | PO date and value (retainers use one annual blanket PO) |

## invoices.csv (3,668 rows)
| Column | Description |
|---|---|
| invoice_id | Internal ID `INV000001`… |
| vendor_id, vendor_invoice_no | Vendor and the vendor's own invoice number |
| po_id | Linked PO; empty for non-PO invoices |
| invoice_date, posting_date | Vendor invoice date and AP posting date |
| amount | Invoice amount |
| approver_id, entered_by | Approving employee and AP clerk who keyed the invoice |

## payments.csv (3,668 rows)
| Column | Description |
|---|---|
| payment_id, invoice_id | One payment per invoice |
| payment_date, paid_amount | When and how much was paid |
| paid_to_account | Bank account the payment went to (used by T10) |

## injected_anomalies.csv (238 rows): answer key
| Column | Description |
|---|---|
| invoice_id | Affected invoice |
| scheme | One of 11 injected schemes (see README) |
| note | How the case was created |

This file exists only because the data is synthetic, so the tests can be scored. It is never used as a model input.

## Legitimate patterns built in on purpose
These make the false-positive rates realistic:
- 15 consulting retainers bill fixed round monthly fees (round-sum false positives).
- 6 utilities bill without POs under policy.
- A year-end close batch is posted on Saturday 27 Dec 2025 (weekend false positives).
- 25% of POs are invoiced in two instalments.
